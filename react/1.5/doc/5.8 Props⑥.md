# keyプロパティ

ここまでで、`map()` を使って

=> **データからコンポーネントを表示する方法** を学びました。

---

## Reactのすごいところ

今回のFood Journalアプリでは、

=> **表示はデータによって決まる（データ駆動）**

という仕組みになっています。

つまり

```js
// data.js にデータを追加するだけ
```

=> 自動で画面に表示されるようになります

---

## 実際にどうなる？

もし `data.js` にデータを追加すると…

=> 新しい `Recipe` が自動で表示される

=> コードを増やす必要なし！

---

## でも問題が出る

コンソールにこんな警告が出ます

```
Each child in a list should have a unique "key" prop
```

### これはどういう意味？

=> Reactはリスト（配列）を表示するとき、

* どの要素がどこにあるか
* どれが追加・削除されたか

を管理する必要があります

そのために

=> **各要素に「key」が必要**

---

## 解決方法

`map()` の中で `key` を追加します

```jsx
const recipeElements = recipes.map((recipe) => {
  return (
    <Recipe
      key={recipe.id}
      name={recipe.name}
      img={recipe.img}
      ingredients={recipe.ingredients}
      description={recipe.description}
    />
  );
});
```

### ポイント

* `key` は必ず必要
* 名前は **必ず `key`**
* 値は **ユニーク（重複しない）**

---

## なぜidを使うの？

```js
{
  id: 1,
  name: "カレーライス"
}
```

=> idは一意（ユニーク）だから安全

---

## よくあるミス

```jsx
key={1}
```

=> 全部同じになる → NG


```jsx
key={recipe.name}
```

=> 同じ料理名があったらバグになる

---

## indexを使う方法

```jsx
recipes.map((recipe, index) => {
  return <Recipe key={index} />;
});
```

=> 一応動く


でも

=> **基本的にはおすすめしない**

理由：

* 順番が変わるとバグの原因になる
* 要素の追加・削除に弱い

---

## いつindex使っていい？

* データが固定
* 並び順が変わらない

=> 今回のような簡単なアプリならOK

---

## まとめ

* Reactで配列を表示するときは `key` が必要
* `key` はユニークな値にする
* できれば `id` を使う
* `index` は最後の手段
