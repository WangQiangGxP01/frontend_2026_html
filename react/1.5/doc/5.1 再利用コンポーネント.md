# 再利用できるコンポーネント

### 身近なWebサイトでも使われている考え方

この「再利用できるコンポーネント」の考え方は、いろいろなWebサイトで使われています。

---

#### YouTube の場合

YouTubeの動画一覧を見ると、動画ごとに表示される内容は違います。

![](\nodebox\doc\images\youtube.png)

* サムネイル画像
* 動画タイトル
* チャンネル名
* 再生回数
* ...

でも、見た目の形はほとんど同じです。

=> 同じコンポーネントに違うデータを入れて表示している

---

#### Amazon の場合

Amazonの商品一覧でも同じです。

![](\nodebox\doc\images\amazon.png)

* 商品画像
* 商品名
* 価格
* 評価

商品ごとに情報は違いますが、レイアウトは同じです。

=> 商品データをもとに、同じコンポーネントを繰り返し表示している

---
### 今のアプリの構造と問題点

まず、今作っている Food Journal アプリの構造を見てみましょう。

[`App.js`](../src/App.js)と[`components/Recipe.js`](../src/components/Recipe.js)を確認してください

ポイント： 
- `Recipe` コンポーネントを3回並べて表示しています。
- 中身（料理名・材料）を直接書いています。

---

## ここで何が起きている？

今の状態だと、

```jsx
<Recipe />
<Recipe />
<Recipe />
```

と書いても、すべて同じ内容になります。

つまり、

* 1つ目 → カレー
* 2つ目 → カレー
* 3つ目 → カレー

=> **全部同じ料理になってしまう**

### なぜ問題？

これまで作ってきた `Recipe` コンポーネントは、
中の内容をすべて直接書いていたので、**同じ料理しか表示できない状態**でした。

たとえば、「カレーライス」や「材料」などをそのままコードに書いてしまうと、
別の料理（寿司やラーメン）を表示したいときには、
また新しく同じようなコンポーネントを書かなければなりません。

---

## Reactではどう考える？

でも、Reactではそんな作り方はあまりしません。

Reactでは、

=> **同じ形の部品（コンポーネント）を1つ作る**

=> **中身（データ）だけを変えて使い回す**

という考え方がとても大切です。

### イメージ

今（NG）

```jsx
<Recipe />  // カレー
<Recipe />  // カレー
<Recipe />  // カレー
```

理想（OK）

```jsx
<Recipe name="カレー" />
<Recipe name="寿司" />
<Recipe name="ラーメン" />
```

=> **同じコンポーネント + 違うデータ**

---

## まとめ

* `App.js` はコンポーネントを並べている
* `Recipe.js` は見た目を定義している
* でも今は中身が固定なので再利用できていない
