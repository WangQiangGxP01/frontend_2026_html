# useStateと配列の分割代入（Reactでのstateの使い方）

### 今のやり方の問題

```jsx
result[0]
```

=> 書き方が分かりにくい
=> ユーザーが操作できない

---

## useStateの戻り値

`React.useState()` を呼び出すと、配列が返ってきます。

```jsx
const result = React.useState("yes");

//戻り値：
["yes", 関数]
```

---

## 配列の分割代入（Destructuring）

このままだと `result[0]` のように書く必要があり、少し分かりにくいです。

そこで

```jsx
const [value, func] = React.useState("yes");
```

=> 配列を分解して受け取る

* `value` → 現在のstateの値
* `func` → stateを更新する関数

---

### 命名ルール

* 名前は自由に決められる
* 自分で分かりやすい名前にできる

Reactでは一般的に

```jsx
const [abc, setAbc] = React.useState(○○);

//例
const [isHappy, setIsHappy] = React.useState("yes");
const [count, setCount] = React.useState(0);
```

* state → `isHappy`
* 更新関数 → `setIsHappy`

### なぜこの名前？

=> 「stateをセットする関数」という意味

---

## stateを変更する方法

#### NG（直接変更）

```jsx
let isHappy = "yes";
isHappy = "no";
```

=> 画面は更新されない

#### 正しい方法

```jsx
setIsHappy("no");
```

=> Reactが再レンダーする

### なぜ？

=> `setIsHappy()` を呼ぶと

1. stateが更新される
2. コンポーネントが再実行される
3. 画面が更新される

---

## 注意：無限ループ

```jsx
setIsHappy("no");
```

これを関数の中で直接実行すると

=> 無限ループになる

### なぜ？

```text
setState → 再レンダー → setState → 再レンダー → ...
```

=> 永遠に繰り返される


### 正しい使い方（イベントと一緒に使う）

#### ① 関数を作る

```jsx
function handleClick() {
  setIsHappy("definitely");
}
```
#### ② ボタンに設定

```jsx
<button onClick={handleClick}>
  {isHappy}
</button>
```

#### 結果

=> ボタンをクリックすると

=> stateが更新される

=> 画面も更新される

---

## まとめ

* `useState()` は配列を返す
* 分割代入で使いやすくする
* stateは直接変更しない
* `setState`関数を使う
* イベントと組み合わせる
