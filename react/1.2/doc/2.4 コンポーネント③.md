# Reactコンポーネントの基本 ③

## export / import の基本（コンポーネント分割）

### 目的

これまで `index.jsx` にすべてのコンポーネントを書いていましたが、  実際の開発ではコードが長くなりすぎてしまいます。

そのため、**コンポーネントを別ファイルに分ける**必要があります。

---

### Before（すべて1ファイル）

```jsx
function Navbar() {
  return <nav>...</nav>;
}

function BodyContent() {
  return <main>...</main>;
}

function Footer() {
  return <footer>...</footer>;
}

root.render(
  <div>
    <Navbar />
    <BodyContent />
    <Footer />
  </div>
);
```

=> 小さいうちは問題ないですが、コードが増えると見づらくなります

---

### After: Reactでの改善（ファイル分割）

#### ① Navbar.jsx を作成
```jsx
// Navbar.jsx

export default function Navbar() {
  return (
    <nav className="navbar navbar-dark bg-dark">
      My App
    </nav>
  );
}
```

#### ② index.jsx で読み込む
```jsx
// index.jsx

import Navbar from "./Navbar";

root.render(
  <div>
    <Navbar />
  </div>
);
```

---

## Reactの考え方

Reactでは、UIを小さな部品（コンポーネント）に分けて管理します。

=> コンポーネントごとにファイルを分けるのが基本です

#### ① export（外に公開する）
```jsx
export default function Navbar() {
  return (
    <nav>
      ...
    </nav>
  );
}
```

または
```jsx

function Navbar() {
  return (
    <nav>
      ...
    </nav>
  );
}
export default Navbar;
```

=> このファイルの外でも使えるようにする

#### ② import（読み込む）
```jsx
import Navbar from "./Navbar";
```

=> 他のファイルからコンポーネントを持ってくる

### なぜ分割するのか？
- ファイルがスッキリする
- 再利用しやすくなる
- チーム開発しやすくなる

=> 実務では必須の考え方

---

## 注意点
```jsx
// OK
import Navbar from "./Navbar";

// NG
import { Navbar } from "./Navbar";
```

- export default の場合は {} は不要
- "./" は「同じフォルダ」を意味する


### 補足
```jsx
export function Navbar() {}
//exportした時defaultがなければ↓
import { Navbar } from "./Navbar";
```
=> 名前は一致させる必要がある

```jsx
import { Navbar as MyNavbar } from "./Navbar"; // 別名はOK
```

---

## まとめ

Reactの基本の流れ（分割編）：
- コンポーネントを別ファイルにする
- exportで外に出す
- importで読み込む
